Projekt Django od zera:
aplikacja „Lista zadań”

Zbudujesz pierwszy projekt w Django — od pustego folderu po działającą stronę z listą zadań. Polecenia wpisujesz w symulowanym terminalu u dołu ekranu, a efekty obserwujesz w wirtualnych plikach i przeglądarce. Strona prowadzi Cię za rękę i sprawdza każdy krok.

⏱ ≈ 60 minut 🎯 technik programista 🧰 VS Code · Python · Django 💾 postęp zapisuje się automatycznie
Rozpocznij kurs ↓
01

Przygotowanie projektu

⏱ 5 minut

Utwórz na komputerze folder django_cwiczenie — w nim powstanie cały projekt. Następnie otwórz go w Visual Studio Code i wybierz w menu Terminal → New Terminal (lub Ctrl+`).

Sprawdź, czy Python jest zainstalowany:

PS>python --version

Jeżeli to nie działa w systemie Windows, spróbuj py --version. Powinieneś zobaczyć coś podobnego do Python 3.12.7.

Utwórz teraz folder projektu i wejdź do niego:

PS>mkdir django_cwiczenie
PS>cd django_cwiczenie
💡Wskazówka: po cd django_cwiczenie ścieżka w zachęcie terminala zmieni się na …\django_cwiczenie> — wszystkie kolejne polecenia wykonujesz właśnie w tym folderze.
02

Środowisko wirtualne

⏱ 5 minut

Środowisko wirtualne (venv) to odseparowana „koperta” na biblioteki Twojego projektu — dzięki niej paczki zainstalowane w ćwiczeniu nie pomieszają się z innymi projektami.

PS>python -m venv venv

Polecenie nic nie wypisuje — po prostu tworzy folder venv/. Aktywuj je (Windows):

PS>venv\Scripts\activate

Jeżeli wszystko działa, przed ścieżką w terminalu pojawi się (venv). Teraz zainstaluj Django:

PS>pip install django

I sprawdź instalację:

PS>django-admin --version
💡pip to menedżer paczek Pythona — pobiera biblioteki z repozytorium PyPI. Po aktywacji venv instaluje je w środku środowiska, nie globalnie.
03

Utworzenie projektu Django

⏱ 5 minut

Projekt to „plecak” aplikacji: konfiguracja, ustawienia i adresy URL. Utwórz go poleceniem:

PS>django-admin startproject todo_project .
⚠️Kropka na końcu jest ważna! Powoduje, że projekt powstaje w bieżącym folderze (obok venv/), a nie w dodatkowym podfolderze.

Struktura projektu powinna wyglądać mniej więcej tak:

django_cwiczenie/ ├── venv/ ├── manage.py └── todo_project/ ├── __init__.py ├── settings.py ├── urls.py ├── asgi.py └── wsgi.py

Najważniejszy plik to manage.py — służy między innymi do wykonywania poleceń związanych z projektem Django (uruchamianie serwera, tworzenie aplikacji, migracje). Podgląd plików znajdziesz w panelu na dole, w karcie Pliki.

04

Uruchomienie serwera

⏱ 5 minut

Django ma wbudowany serwer developerski. Wpisz:

PS>python manage.py runserver

W terminalu powinien pojawić się adres podobny do http://127.0.0.1:8000/. Przełącz się na kartę Przeglądarka w panelu na dole i otwórz ten adres — jeżeli zobaczysz stronę startową Django (rakieta 🚀), projekt działa prawidłowo.

🛑Serwer zatrzymasz skrótem Ctrl+C — jest do tego przycisk na pasku terminala (działa tylko, gdy serwer biega). Przed kolejnymi krokami zatrzymaj serwer.
05

Utworzenie aplikacji

⏱ 5 minut

Projekt Django może składać się z wielu aplikacji. Aplikacja realizuje konkretną część funkcjonalności — w naszym przypadku będzie to lista zadań: aplikacja tasks.

PS>python manage.py startapp tasks

W projekcie pojawi się nowy katalog:

tasks/ ├── __init__.py ├── admin.py ├── apps.py ├── migrations/ ├── models.py ├── tests.py └── views.py
Pytanie kontrolne: czym różni się projekt Django od aplikacji Django?
Projekt jest całym systemem, natomiast aplikacja realizuje konkretną część jego funkcjonalności. W jednym projekcie może działać wiele aplikacji (np. tasks, formularz, blog).
06

Dodanie aplikacji do projektu

⏱ 5 minut

Otwórz todo_project/settings.py, znajdź INSTALLED_APPS = [ i dopisz na końcu listy 'tasks', — dzięki temu Django zacznie „widzieć” Twoją aplikację:

todo_project/settings.py 
INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    'tasks',   <— dopisz tę linię
]

Zapisz plik przyciskiem na karcie — w prawdziwym VS Code wystarczy Ctrl+S.

07

Utworzenie pierwszego widoku

⏱ 5 minut

Widok to funkcja, która przyjmuje żądanie (request) i zwraca odpowiedź. Otwórz tasks/views.py i wpisz:

tasks/views.py 
from django.shortcuts import render

def index(request):
    tasks = [
        "Nauczyć się Django",
        "Utworzyć pierwszy widok",
        "Przygotować szablon HTML",
        "Uruchomić aplikację",
    ]
    return render(request, "tasks/index.html", {
        "tasks": tasks,
    })

Widok przygotowuje dane (listę zadań) i przekazuje je do szablonu HTML funkcją render(). Tak właśnie przesyła się dane z Pythona do HTML.

08

Podłączenie adresów URL

⏱ 5 minut

Teraz musimy powiedzieć Django: „kto odpowiada na adres /?”. Otwórz todo_project/urls.py i zmień zawartość na:

todo_project/urls.py 
from django.contrib import admin
from django.urls import path
from tasks.views import index

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', index),
]

Ścieżka '' (pusty adres) to strona główna. Kolejność jest istotna: Django sprawdza urlpatterns od góry i wybiera pierwsze dopasowanie.

09

Szablon HTML

⏱ 5 minut

Widok zwraca "tasks/index.html", więc taki plik musimy utworzyć. W folderze tasks utwórz strukturę templates/tasks/, a w niej plik index.html:

tasks/ ├── templates/ │ └── tasks/ │ └── index.html ← nowy plik ├── views.py └── …

Wpisz do niego kod poniżej. Zwróć uwagę na znaczniki Django: {% for %} to logika (pętla po zadaniach), a {{ task }} wstawia wartość:

tasks/templates/tasks/index.html 
<!DOCTYPE html>
<html lang="pl">
<head>
    <meta charset="UTF-8">
    <title>Lista zadań</title>
</head>
<body>
    <h1>Moja lista zadań</h1>
    <ul>
    {% for task in tasks %}
        <li>{{ task }}</li>
    {% endfor %}
    </ul>
</body>
</html>
10

Podgląd w przeglądarce

⏱ 5 minut

Włącz serwer ponownie i zobacz efekt swojej pracy:

PS>python manage.py runserver

Otwórz http://127.0.0.1:8000/ w karcie Przeglądarka. Powinna pojawić się lista zadań — dokładnie ta, którą wpisałeś w views.py.

👀Przepływ danych: przeglądarka → URL → views.py → dane → szablon HTML → strona WWW. Jeśli zobaczysz błąd TemplateDoesNotExist, sprawdź krok 9 (nazwa i lokalizacja pliku).
11

Dodanie CSS

⏱ 5 minut

Teraz poprawimy wygląd strony. W folderze tasks utwórz folder static/, w nim tasks/, a następnie plik style.css:

tasks/ ├── static/ │ └── tasks/ │ └── style.css ← nowy plik └── templates/tasks/index.html
tasks/static/tasks/style.css 
body {
    font-family: Arial, sans-serif;
    background-color: #f2f2f2;
    margin: 40px;
}
.container {
    max-width: 600px;
    margin: auto;
    background-color: white;
    padding: 30px;
    border-radius: 10px;
}
h1 { color: #333; }
li {
    margin: 10px 0;
    padding: 10px;
    background-color: #e8f0fe;
    border-radius: 5px;
}

Żeby podpiąć arkusz, zmień tasks/templates/tasks/index.html: dodaj na górze {% load static %} oraz link do pliku w <head>, a listę zawiń w kontener:

tasks/templates/tasks/index.html (wersja 2) 
{% load static %}
<!DOCTYPE html>
<html lang="pl">
<head>
    <meta charset="UTF-8">
    <title>Lista zadań</title>
    <link rel="stylesheet" href="{% static 'tasks/style.css' %}">
</head>
<body>
    <div class="container">
        <h1>Moja lista zadań</h1>
        <ul>
        {% for task in tasks %}
            <li>{{ task }}</li>
        {% endfor %}
        </ul>
    </div>
</body>
</html>
💡{% static 'tasks/style.css' %} zamienia się na prawdziwy adres pliku statycznego. Katalog statycznych nosi nazwę aplikacji, żeby pliki różnych aplikacji się nie mieszały.

Odśwież stronę w karcie Przeglądarka — wygląda zupełnie inaczej! 🎨

12

Zadania dla ucznia

⏱ 10 minut

Teraz samodzielnie rozbuduj aplikację. Odhacz kolejne zadania — podpowiedzi są w treści każdej karty.

W views.py dodaj minimum 3 własne zadania, np. dotyczące HTML, CSS, Pythona, baz danych, JavaScriptu.

Zamiast listy <ul> wykorzystaj <ol> — wynik: 1. Nauczyć się Django, 2. Utworzyć pierwszy widok…

Pod listą wyświetl Liczba zadań: 4. Podpowiedź: w widoku dodaj "number": len(tasks), a w HTML — <p>Liczba zadań: {{ number }}</p>.

Zmodyfikuj style.css: inny kolor nagłówka, inne tło zadań, większe marginesy strony, zaokrąglone rogi elementów listy.

Bonus: Formularz ucznia

⏱ 30 minut

Druga część ćwiczeń z lekcji: własny projekt mojprojekt z formularzem, który przyjmuje dane metodą POST i wyświetla je na osobnej stronie. Kroki powtarzają schemat listy zadań — poniżej skrót z gotowym kodem.

Krok B1 — projekt i aplikacja
PS>django-admin startproject mojprojekt .
PS>python manage.py startapp formularz

Utwórz folder formularz_django, venv (python -m venv venv → venv\Scripts\activate → pip install django) i dopisz 'formularz', do INSTALLED_APPS.

Krok B2 — widok i szablon formularza

W formularz/views.py:

formularz/views.py
from django.shortcuts import render

def formularz(request):
    return render(request, 'formularz.html')

W folderze formularz utwórz templates/, a w nim formularz.html:

formularz/templates/formularz.html
<!DOCTYPE html>
<html lang="pl">
<head>
    <meta charset="UTF-8">
    <title>Formularz ucznia</title>
</head>
<body>
    <h1>Formularz ucznia</h1>
    <form method="post">
        {% csrf_token %}
        <label>Imię:</label>
        <input type="text" name="imie">
        <br><br>
        <label>Nazwisko:</label>
        <input type="text" name="nazwisko">
        <br><br>
        <label>Klasa:</label>
        <input type="text" name="klasa">
        <br><br>
        <button type="submit">Wyślij</button>
    </form>
</body>
</html>
🔐{% csrf_token %} dodaje ukryty token ochrony przed CSRF — bez niego Django odrzuci żądanie POST.
Krok B3 — adresy URL
mojprojekt/urls.py
from django.contrib import admin
from django.urls import path
from formularz.views import formularz

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', formularz),
]
Krok B4 — obsługa POST i strona wyniku

Zmień widok tak, aby odbierał dane z formularza:

formularz/views.py (wersja 2)
def formularz(request):
    if request.method == 'POST':
        imie = request.POST.get('imie')
        nazwisko = request.POST.get('nazwisko')
        klasa = request.POST.get('klasa')
        return render(request, 'wynik.html', {
            'imie': imie,
            'nazwisko': nazwisko,
            'klasa': klasa
        })
    return render(request, 'formularz.html')

W templates/ utwórz wynik.html:

formularz/templates/wynik.html
<!DOCTYPE html>
<html lang="pl">
<head>
    <meta charset="UTF-8">
    <title>Wynik</title>
</head>
<body>
    <h1>Dane ucznia</h1>
    <p>Imię: {{ imie }}</p>
    <p>Nazwisko: {{ nazwisko }}</p>
    <p>Klasa: {{ klasa }}</p>
</body>
</html>

Uruchom python manage.py runserver, wpisz dane w formularzu i kliknij Wyślij. Django odbierze dane (imie, nazwisko, klasa) i przekaże je do wynik.html.

🎓Co powinieneś umieć po tym ćwiczeniu: HTML tworzy formularz · views.py odbiera żądanie · request.POST zawiera dane wysłane formularzem · render() wyświetla stronę HTML · {{ imie }} wyświetla dane przekazane z Pythona do HTML.
